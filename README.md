# skillkit — 技能庫治理工具

`mySkill`、`mySkill-private`、`workflow` 等技能倉庫共用的規則、範本與驗證工具。
放在 `D:\develop\AI\skillkit`，與各技能倉庫同層。

## 用法（在技能倉庫根目錄）

```powershell
manage.cmd lint          # 檢查技能是否符合規範
manage.cmd sync          # 注入共用準則、產生 README.md 與 skills.json
manage.cmd sync --check  # CI 用：只檢查是否同步
manage.cmd list          # 列出技能
manage.cmd render        # 重新產生 GEMINI.md 與 CI workflow
```

`manage.cmd` 由 `init` 產生，內容只有三行：cd 到專案根目錄，呼叫 `..\skillkit\manage.py`。
macOS / Linux 請用 `python ../skillkit/manage.py`（同樣在專案根目錄執行）。

## 新專案

```powershell
python D:\develop\AI\skillkit\manage.py init --dir D:\develop\AI\<新專案> --repo https://github.com/<owner>/<repo>
```

接著進入新專案：

```powershell
manage.cmd new my-first-skill --category exam --label "公職 / 考試" --summary "一句話簡介" --triggers "關鍵字A,關鍵字B"
```

## 檔案

| 路徑 | 用途 |
|---|---|
| `manage.py` | 全部邏輯（lint / sync / render / init / new / list） |
| `templates/GEMINI.md` | 各專案 `GEMINI.md` 的來源（佔位符：`{{SITE_NAME}}`、`{{REPO_URL}}`、`{{RAW_BASE}}`、`{{ARCHIVE_ROOT}}`、`{{KIT_REPO}}`、`{{KIT_REF}}`、`{{KIT_CMD}}`） |
| `templates/skills-ci.yml` | 各專案 CI workflow 的來源（會 checkout 本 repo 到 `.skillkit`） |
| `tests/` | pytest 測試 |

## 設計

- 各技能倉庫**不含**治理程式碼，只留 `skills.config.json`、`manage.cmd` 與產生物。
- 規則只有一份：改這裡，所有專案下一次 `lint` / `sync` 就生效。
- `render` 會覆寫 `GEMINI.md` 與 CI（先備份 `.bak`），檔案開頭有 `generated by skillkit` 標記。
